# CCCode 任务进度与品牌设置设计

## 目标

在现有 CCCode 中同时增加结构化任务计划/执行进度能力，并完成 CCCode 品牌、提交署名、Bark 通知、官网用户可见域名、CC API 余额和左侧 Logo 的统一优化。

## A. 任务计划与执行进度

用户发送任务后，Agent 自动生成结构化任务计划并立即执行，不等待用户确认。计划是现有 Agent/kernel 执行状态的结构化投影，不创建第二套执行引擎。

### 展示

- 右上角放置紧凑任务状态入口：`任务计划 · 0/6`、`执行中 · 第 3/6 步 · 01:24` 等。
- 点击入口从右侧展开约 320–380px 的任务抽屉。
- 计划生成后抽屉短暂自动展开约 1–2 秒；失败时保持展开。
- 单个当前 Agent 的顺序任务优先，多 Agent 依赖图、甘特图和拖拽排序不在本次范围。

### 状态与时间

步骤状态：`pending`、`running`、`completed`、`failed`、`paused`、`cancelled`。

- 待执行显示估算范围；
- 执行中显示实时累计耗时；
- 完成/失败显示实际耗时；
- 暂停显示暂停前累计耗时。

### 控制

- 暂停：当前命令自然完成，不启动下一步；
- 继续：从未完成步骤继续；
- 停止：确认后停止新步骤，向现有 Agent 发送停止请求并保留已完成步骤；
- 失败：自动暂停后续步骤，支持重试失败步骤、继续或停止。

### 恢复

窗口关闭、Agent 切换后任务仍由现有后台会话运行；重新打开恢复任务状态。计划持久化失败不得阻塞 Agent 执行；冲突时以 Agent/kernel 真实状态为准。

## B. CC API 卡片与余额

CC API 模型卡片扩展到约 280–320px，第二行显示连接状态、模型数量和余额，例如：

```text
CC API                         刷新模型 >
已连接 · 7 个模型 · 余额 $12.50
```

余额来自现有 `/auth/me` profile 数据：有值显示两位小数，零值显示 `$0.00`，缺失则隐藏；刷新失败保留上次余额。

## C. 品牌与主题

- `Bao Light` 改为 `CC Light`；
- `Bao Dark` 改为 `CC Dark`；
- 旧主题配置迁移到新名称；
- 左侧栏底部放置 CC Logo，使用现有 `assets/branding/cccode_logo.svg`，点击进入 About，悬停显示 `CCCode`。

## D. 提交署名

保留“跟随 Agent”和“不署名”，并把 CCCode 署名改为名称/邮箱均可编辑：

- 默认名称：`CCCode`；
- 默认邮箱：`noreply@ccapitoken.cc`；
- 输出 `Co-Authored-By: <name> <email>`；
- 名称不能为空，邮箱做基本格式校验；
- 旧 `CCCode <noreply@baocode.dev>` 迁移到新默认值；
- 设置对之后启动的 Agent 生效。

## E. Bark 通知

通知设置增加完整 Bark URL 输入框。URL 为空不发送；已启用的 needs-input/finished 事件同步发送 Bark；请求失败不影响系统通知、提示音或 Agent；不在日志中输出完整 URL/Key。

## F. 官网分阶段域名迁移

第一阶段只迁移用户可见内容到 `https://ccapitoken.cc`：About、README、官网按钮、帮助文档、推荐上游和用户可见文案。

暂时保留下载 CDN、自动更新 manifest、统计、CI 上传、远程服务器发布等内部基础设施 URL，后续 DNS/CDN/HTTPS 完成后再迁移。

## G. 验收

- 任务计划生成后自动开始并可查看、暂停、继续、停止、重试；
- CC API 卡片可完整显示余额；
- 主题和署名完成 CCCode 迁移且旧配置可用；
- Bark URL 可配置且失败隔离；
- 用户可见官网域名改为 ccapitoken.cc，内部发布地址未误改；
- 左侧 CC Logo 显示、点击和主题适配正确；
- 普通无任务计划对话保持原行为。
