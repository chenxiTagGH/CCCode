# 任务计划与执行进度设计

## 目标

在 CCCode 的 Agent 对话中增加结构化任务计划和执行进度展示：用户发送任务后，Agent 先生成任务清单，随后自动开始执行；右上角显示紧凑状态入口，点击后从右侧展开详细任务抽屉，展示步骤状态、预计耗时、实际耗时，并提供暂停、继续和停止控制。

## 用户体验

### 自动执行流程

```text
用户发送任务
  → Agent 生成结构化任务清单
  → 右上角显示任务入口
  → 任务抽屉短暂自动展开
  → 自动开始第一步
  → 步骤完成后自动进入下一步
```

不等待用户点击“开始”。计划生成后自动执行。

### 右上角入口

入口位于当前对话窗口右上角工具区域附近，默认保持紧凑，不长期占用聊天空间。示例：

- `任务计划 · 0/6`
- `执行中 · 第 3/6 步 · 01:24`
- `已暂停 · 第 3/6 步`
- `任务完成 · 6/6`
- `任务失败 · 第 3/6 步`

入口颜色与状态对应：灰色待开始、蓝色执行中、绿色完成、黄色暂停、红色失败。

### 右侧任务抽屉

点击入口后展开约 320–380px 宽的右侧抽屉，显示：

- 任务标题；
- 完成数量和总数量；
- 总耗时；
- 每个步骤的名称、状态、预计时间或实际耗时；
- 当前步骤的运行状态；
- 底部的暂停/继续和停止操作。

任务生成后抽屉可自动展开约 1–2 秒，随后自动收起；任务失败时保持展开。

### 步骤状态

步骤状态为：

```text
pending   待执行
running   执行中
completed 已完成
failed    失败
paused    已暂停
cancelled 已停止
```

### 时间显示

- `pending`：显示估算范围，例如“预计 30 秒–1 分钟”；
- `running`：显示实时累计时间，例如“已用时 01:24”；
- `completed`：显示实际耗时，例如“已完成 · 用时 42 秒”；
- `failed`：显示失败时的累计耗时；
- `paused`：显示暂停前的累计耗时。

估算使用范围，不显示没有依据的精确秒数。

## 控制行为

### 暂停

点击暂停后，不启动下一个步骤。当前正在运行的命令允许自然完成，避免中断 SSH、Shell 或文件写入。状态变为 `paused`，按钮变为“继续执行”和“停止”。

### 继续

从当前未完成步骤继续执行，已完成步骤不重复执行。

### 停止

点击停止后显示确认对话框。确认后：

- 不再启动新步骤；
- 向当前 Agent 发送停止请求；
- 保留已完成步骤和耗时；
- 任务状态变为 `cancelled`。

### 失败

某一步失败后暂停后续步骤，并显示错误原因。用户可以：

- 重试失败步骤；
- 继续执行；
- 停止任务。

重试只重新执行失败步骤，不重复已完成步骤。

## 数据模型

任务计划保存为结构化状态，而不是仅从自然语言文本推断：

```text
TaskPlan
├── title
├── status
├── startedAt
├── finishedAt
├── totalElapsed
└── steps
    ├── title
    ├── description
    ├── estimate
    ├── status
    ├── startedAt
    ├── finishedAt
    └── error
```

第一版的状态模型需要支持：创建计划、开始步骤、完成步骤、失败、暂停、继续、停止、重试失败步骤和耗时累计。

## 与现有 Agent 执行的关系

任务计划是 Agent 执行状态的结构化投影，不另起一套独立执行引擎。计划控制器负责记录步骤和向现有 Agent/kernel 发送暂停、继续、停止信号；现有会话、工具调用、后台运行和对话记录继续作为真实执行来源。

第一版优先支持当前聚焦 Agent 的单一顺序任务。多 Agent 依赖图、并行任务编排和甘特图不在本次范围内。

## 错误处理与恢复

- 计划解析失败时，保留现有聊天执行流程，不显示虚假的任务清单；
- 任务状态写入失败不应阻塞 Agent 执行；
- 窗口关闭或切换 Agent 后，任务继续由现有后台会话运行，重新打开时恢复任务状态；
- 用户停止任务后，不自动重启；
- 计划状态与已有会话状态冲突时，以 Agent/kernel 的真实状态为准，并将计划标记为失败或需要恢复。

## 验收标准

1. 用户发送任务后能看到结构化任务清单，并自动开始第一步；
2. 右上角有紧凑任务状态入口；
3. 点击入口可展开右侧任务抽屉；
4. 待执行、执行中、已完成、失败、暂停、停止状态正确显示；
5. 未开始步骤显示预计时间，执行后显示实际耗时；
6. 暂停不会启动后续步骤，继续可以从未完成步骤恢复；
7. 停止需要确认并保留已完成步骤；
8. 失败后自动暂停，并可重试失败步骤；
9. 窗口或 Agent 切换不会丢失任务状态；
10. 不影响没有结构化任务计划的普通对话。

## 范围外

- 多 Agent 任务依赖图；
- 甘特图和拖拽排序；
- 自动重排所有任务顺序；
- 精确可靠的耗时预测；
- 独立于现有 Agent/kernel 的第二套执行引擎。
